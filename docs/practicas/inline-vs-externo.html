Caso 1 · Inline frente a una clase

Disponible
<span class="badge badge--success" style="background: #FDE68A; color: #92400E;">Disponible</span>

Resultado: Gana el estilo inline (amarillo). La declaración del atributo style tiene más prioridad que cualquier selector de la hoja, aunque .badge--success sea más específica que .badge.

Caso 2 · !important en la hoja frente a inline

Disponible
<span class="badge prueba-importante" style="background: #FDE68A; color: #92400E;">Disponible</span>

Resultado: Gana la hoja (azul). Una declaración con !important en la hoja externa supera a una inline normal: el nivel de importancia se compara antes que el origen y la especificidad.

Caso 3 · Inline con !important

Disponible
<span class="badge prueba-importante" style="background: #FECACA !important; color: #991B1B !important;">Disponible</span>

Resultado: Gana el inline (rojo). Si las dos son !important, vuelve a mandar el atributo style. Es la única forma de ganar a un inline !important, por eso es tan difícil de mantener.

Caso 4 · Lo que el inline no puede hacer

Enlace con estilo inline Enlace con la clase .link
<a href="#conclusion" style="color: #0F766E; text-decoration: underline;">Enlace con estilo inline</a>
<a class="link" href="#conclusion">Enlace con la clase .link</a>

Resultado: Pasa el ratón y usa Tab: solo el enlace con clase cambia en :hover y muestra el anillo de :focus-visible. En un atributo style no se pueden escribir pseudoclases, media queries ni ::before.

Conclusión técnica

El estilo inline funciona y tiene la prioridad más alta, pero no sigue los temas, no admite estados ni media queries y obliga a repetir cada valor. Por eso en la aplicación no hay ningún atributo style: todo el aspecto sale de clases del Design System en hojas externas. Solo lo usaríamos para un valor que cambie en cada elemento y no pueda ser una clase (por ejemplo, el ancho de una barra de progreso calculado en el servidor) y, aun así, mediante una custom property: style="--progreso: 40%".
